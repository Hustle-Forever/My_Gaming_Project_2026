The idea

Describe it. Approve it. It's live.

Describe what you want. Review what changes. Approve. It's live. And if anything breaks — one click puts it back.

The problem today

Every new feature means hiring a developer or fighting Lua tutorials — and live admin work is all done by hand.

The M2 way

One platform where a server owner speaks or types, in Arabic or English, and the server builds and runs itself — safely.

What it does

Two ways to talk to your server

Run Built & tested

Live control of the game, in the moment.

  • Spawn vehicles, set weather & time, heal, and more
  • Voice or text, Arabic and English
  • Only ever a fixed, approved list of actions

Build Next

An AI developer that ships features for you.

  • Reads your server, writes the FiveM resource
  • Shows you every changed file before anything runs
  • Installs on approval — with backup & one-click rollback

Architecture

Five layers, each doing one job — provider-swappable and multi-tenant from day one.

ClientThe console app + owner dashboard — dark/light, EN/ARHTML · JS
PlatformAuth, pay-gate, provider layer, command queueVercel functions
DataTenants, encrypted keys, queue — locked by rulesFirebase
AIInterprets intent inside a closed, safe action setGemini · Claude-ready
ServerThe bridge that runs actions & installs code in-gameFiveM · Lua
Non-negotiables

Safety, by design

Never break the server

Staging-first, and a proven rollback for every change.

Approve before apply

Nothing changes without you seeing it first.

Backed up & reversible

Every write is saved first; one click restores it.

Least privilege

Keys encrypted; access scoped to only what's needed.

Closed by construction

The AI can only act within a defined, safe set.

Honest uncertainty
